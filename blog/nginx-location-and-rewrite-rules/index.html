Nginx - location and rewrite rules

2017.01.19draft

Source: Sean's Notes

0x00 Overview

  • nginx is on the server side.

  • location and rewrite are two functions of nginx configuration.

  • location can capture requesting url and do some operations like proxy_pass based on the result.

  • rewrite can capture requesting url and modify it to a new url, then send back 301-303 response to client or just silently redirect it on the server and do not notice client.

  • location and rewrite are under server section, which means they do not need to match the host name.

  • for example, the requesting full url is http://test.com/this/is/a/url, location and rewrite will only capture '/this/is/a/url'.

0x01 location matching rule

Example:

location  = / {
  # 精确匹配 / ，主机名后面不能带任何字符串
  # Competely and only match '/', any extra characters after '/' will fail this rule.
  [ configuration A ]
}
location  / {
  # 因为所有的地址都以 / 开头，所以这条规则将匹配到所有请求
  # 但是正则和最长字符串会优先匹配
  # This rule will match every url since every url starts with a '/'
  # But the reg exp matching and longest string matching are of higher priority.
  [ configuration B ]
}
location /documents/ {
  # 匹配任何以 /documents/ 开头的地址，匹配符合以后，还要继续往下搜索
  # 只有后面的正则表达式没有匹配到时，这一条才会采用这一条
  # Match url start with '/documents/', but will not stop searching other rules.
  # This rule is going to work only if no other reg or longer string rule matches.
  [ configuration C ]
}
location ~ /documents/Abc {
  # 匹配任何以 /documents/Abc 开头的地址，匹配符合以后，还要继续往下搜索
  # 只有后面的正则表达式没有匹配到时，这一条才会采用这一条
  # Match url start with '/documents/Abc', but will not stop searching other rules.
  # This rule is going to work only if no other reg or longer string rule matches.
  [ configuration CC ]
}
location ^~ /images/ {
  # 匹配任何以 /images/ 开头的地址，匹配符合以后，停止往下搜索正则，采用这一条。
  # Match url start with '/images/', but will not stop searching other rules.
  [ configuration D ]
}
location ~* \.(gif|jpg|jpeg)$ {
  # 匹配所有以 gif,jpg或jpeg 结尾的请求
  # 然而，所有请求 /images/ 下的图片会被 config D 处理，因为 ^~ 到达不了这一条正则
  [ configuration E ]
}
location /images/ {
  # 字符匹配到 /images/，继续往下，会发现 ^~ 存在
  [ configuration F ]
}
location /images/abc {
  # 最长字符匹配到 /images/abc，继续往下，会发现 ^~ 存在
  # F与G的放置顺序是没有关系的
  [ configuration G ]
}
location ~ /images/abc/ {
  # 只有去掉 config D 才有效：先最长匹配 config G 开头的地址，继续往下搜索，匹配到这一条正则，采用
    [ configuration H ]
}
location ~* /js/.*/\.js
